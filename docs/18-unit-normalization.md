# 带单位字段的归一化：值 / 单位 / 原文证据

> 起于一个假设：**comparison 里那批表现差的字段，提示词只让"照抄原文"，是不是拖累了效果？**
> 结论：**假设不成立**（数据见 §2），但顺着查出了三件更有价值的事：
> 真正的失分结构（§3）、金标准的一处编码异常（§5）、以及"单位归一化"的真实收益（§7）。
> 所有数字由 `tools/_unit_*.mjs`、`tools/_scheme_*.mjs` 直接产出。

## 0. 结论速览

| 问题 | 答案 |
|---|---|
| "照抄原文"拖累了效果吗？ | **没有**。写法不同的条目已被语义判定判对（95.8%~98.0%）；`_value`+`_unit` 合计（58.7%）反而**高于** `_desc`（53.4%） |
| 需要把 desc "拆成两个子字段"吗？ | **不需要拆，金标准本来就是三列**：`_desc`（原文）/ `_value`（数）/ `_unit`（单位编码） |
| 那真正的失分在哪？ | 12 列 3,528 条里：**值不同 27.5%｜漏抽 17.0%｜过度填充 9.0%** |
| 单位归一化的收益是什么？ | **不是提分，是判定方式**：**433/844（51.3%）** 的条目从 LLM 语义判定变成**确定性判定**（省钱 + 可复现） |
| 顺手发现的 | `最长随访时间单位` 列 **2020 年后 36% 与表头图例不符**（"周"被编成 code 2=月）→ 金标准问题，已记录 |

## 1. 这几组字段的"三列分工"（金标准本来的设计）

原始表头就写死了单位，且每组分三列：

| 组 | 描述列 | 数值列 | 单位列（编码） | 规范口径 |
|---|---|---|---|---|
| 留针时间 | `needle_retention_desc` | `_value` | `1`=分钟 `2`=小时 | 分钟 |
| 疗程 | `course_desc` | `_value` | `1`=天 `2`=周 | 周 |
| 治疗频次 | `frequency_desc` | `_value` | `1`=天 `2`=周 `3`=1小时 | 次/周 |
| 最长随访时间 | `max_followup_desc` | `_value` | `1`=天 `2`=月 `3`=年 `4`=周 `5`=小时 | 按原文口径 |
| 进针深度 | `insertion_depth_text` | — | — | 毫米 |

**但金标准的 `_desc` 列本身写法不统一**（`tools/_desc_shape_audit.mjs`）：

| 字段 | 纯数字 | 数字+单位 | 文字描述 | 哨兵值 |
|---|---|---|---|---|
| `needle_retention_desc` | **30%** | 32% | 18% | 21% |
| `course_desc` | 5% | **67%** | 26% | 2% |
| `frequency_desc` | 8% | 1% | **89%** | 3% |
| `max_followup_desc` | 1% | 37% | 25% | 37% |
| `insertion_depth_text` | 9% | 7% | 32% | **51%** |

即：`留针时间` 的 `_desc` 其实存的是**分钟数**（`20`/`30`），而 `疗程` 存 `9 weeks`、
`治疗频次` 存 `3 times per week`。**没有一个统一的"desc 该写什么"的口径**——
所以"让 desc 照抄原文"这个指令本身没错，但也确实没法定死。

## 2. 假设检验：照抄原文拖累效果了吗？——没有

三条独立证据（`tools/_desc_failure_breakdown.mjs`、`tools/_scheme_triplet_rates.mjs`、`tools/_desc_to_value_gap.mjs`）：

**证据一：写法不同的条目已经被判对了。** 把每个字段的判定按"金标准与机器的**数字**是否相同"分桶：

| 字段 | 数字相同、只是写法不同 | 该桶加权正确率 |
|---|---|---|
| `needle_retention_desc` | 95 条（占 47%） | **95.8%** |
| `course_desc` | 126 条（占 44%） | **98.0%** |

`4 weeks` vs `four weeks`、`30` vs `30 minutes` 这类，语义判定都给了满分。
**写法不同不是失分点。**

**证据二：`_value`/`_unit` 两列并不比 `_desc` 差。**

| 列组 | 样本 | 加权正确率 |
|---|---|---|
| `*_desc`（原文列） | 1,173 | 53.4% |
| `*_value` + `*_unit`（归一化列） | 2,321 | **58.7%** |

**证据三：模型并没有"只顾抄原文、忘了归一化"。** 全语料 1,400 条里，
"填了 desc 却没填 value/unit"只有 **28 条（2.0%）**，且多数是本来就没有数字的定性描述
（`until the end of gastroscopy`、`during the full RT treatment`）。

## 3. 真正的失分结构（逐比较组直接比对，不经 judged 子集）

⚠️ 口径提醒：`sheets.*.judged` 只包含"无法严格比对"的条目——对编码列**就是失败子集**，
在里面统计会得到"96% 漏抽"这种同义反复的假结论。必须**逐比较组直接比对**。

12 列 × 294 比较组 = **3,528 条**（`tools/_scheme_columns_direct.mjs`）：

| 结论 | 条数 | 占比 |
|---|---|---|
| 一致报 NR | 314 | 8.9% |
| 值一致 | 1,324 | 37.5% |
| **值不同** | **971** | **27.5%** |
| **漏抽**（金标准有值、模型答 NR） | **600** | **17.0%** |
| **过度填充**（金标准说没报告、模型硬填） | **317** | **9.0%** |

逐列看，两类问题各有重灾区：

| 列 | 漏抽 | 过度填充 |
|---|---|---|
| 留针-描述 | 82 | 8 |
| 留针-单位 | 41 | 38 |
| 疗程-数值 | 79 | 2 |
| 频次-数值 | 64 | 8 |
| **随访-数值** | 7 | **70** |
| **随访-单位** | 8 | **79** |

**最长随访是"过度填充"的重灾区**：金标准三列全 NR 的 111 个比较组（37%）里，
模型给 70~79 个硬填了值。原因很清楚——论文常用定性表述
（`until delivery`、`outcomes measured only during hospitalization`），
而模型倾向于"给一个数让表格看起来完整"。

## 4. 已实现的三处改动

### 4.1 `packages/core/src/units.ts`（新）——单位解析与换算

- `parseQuantity()`：`9 weeks` / `3 months` / `30 min` / `24 hours` / `five days` / `15-20 min`（范围）
  / `30分钟` → `{ value, unit, seconds, isRange }`；
- `quantityEqual(a, b)`：换算后同量即相等（`3 months` ≡ `12 weeks`、`30 min` ≡ `0.5 h`），
  带范围的只判**区间相交**；
- **换算约定用项目口径，不用物理常数**：**1 月 = 4 周**、1 周 = 7 天、1 天 = 24 小时、1 小时 = 60 分钟。
  依据：金标准里 `3 months` 对应 `course_value=12`、`course_unit=2`（周）
  （`tools/_unit_convention_scale.mjs` 对全库三列交叉统计）。用 4.345 会与金标准系统性不符。
- `CANONICAL_UNITS`：五组字段的规范单位与编码表（**取自原始 Excel 表头**）。

### 4.2 `tools/prompt_gen.mjs`——提示词新增一节「带单位的三列怎么填」

给 comparison 提示词加了：
1. **规范单位表**（每组字段的 desc/value/unit 各填什么、单位列填哪个编码）；
2. **换算约定**（1 月 = 4 周…）；
3. **具体示例表**（8 行，覆盖 小时→分钟 / 月→周 / 次天→次周 / 定性描述）；
4. **一条硬约束**：只有原文给出明确"数 + 时间单位"时才填 value/unit；
   定性描述时**三列都填 NR**（直接针对 §3 的 317 条过度填充）。

示例（提示词原文的一行）：

| 论文原文 | desc | value | unit | 说明 |
|---|---|---|---|---|
| `a course of 3 months` | `3 months` | `12` | `2` | 月→周（3×4） |
| `retained for 0.5 h` | `0.5 h` | `30` | `1` | 小时→分钟 |
| `follow-up until delivery` | `until delivery` | `NR` | `NR` | **定性描述 → 三列都 NR** |

### 4.3 `tools/llm_eval.mjs`——评测侧改用确定性判定

`unitDecided()`：对上述 5 个字段，先试 `quantityEqual`（换算后同量）与"数字相同"，
能定就**不送 LLM**。

## 5. 顺手发现的**金标准问题**：最长随访时间单位编码

**权威图例**（来自原始 Excel 表头，`build/legend/2015.json`）：
`1=天 2=月 3=年 4=周 5=小时` —— 与 `tools/canonical-field-map.mjs` 一致，提示词没写错。

但**数据自证对不上**（`tools/_unit_legend_verify.mjs`）：把 `_desc` 的原文单位与 `_unit` 编码交叉：

| 原文单位 | code 1 | code 2 | code 3 | code 4 | code 5 |
|---|---|---|---|---|---|
| 天 | **21** | 0 | 0 | 0 | 0 |
| 周 | 2 | **44** | 0 | **40** | 0 |
| 月 | 0 | 16 | 7 | 0 | 0 |
| 年 | 0 | 0 | 2 | 0 | 0 |
| 小时 | 0 | 0 | 0 | 0 | **19** |

"周"同时落在 code 2（图例=月）与 code 4（图例=周）上；"月"落在 code 2 与 3 上。
**按年份看是成片的**（`tools/_unit_legend_anomaly.mjs`）：

| 年份 | 可解析条目 | 与图例不符 | 占比 |
|---|---|---|---|
| 2015–2019 | 41 | **0** | **0%** |
| 2020 | 18 | 8 | 44% |
| 2021 | 13 | 11 | **85%** |
| 2022 | 19 | 4 | 21% |
| 2023 | 16 | 4 | 25% |
| 2024 | 17 | 9 | 53% |
| 2025 | 30 | 20 | 67% |
| 合计 | 154 | **56** | **36%** |

**主要错法：44 条把"周"编成了 code 2（图例=月）**，2020 年后成片出现。

→ 已记录到 `build/unit_legend_anomaly.json`。**这是需要医生拍板的问题**：
2020 年后的这一列到底用哪套图例？（若是标注习惯变了，应该按年份分段处理或统一重编。）
在没有结论前，**不改提示词里的编码表**——那是按表头写的、没错。

## 6. A/B 实测：提示词改动的效果是**混合的**

10 篇（覆盖各年）× 12 列 = 180 条（`tools/_unit_rules_ab.mjs`）：

| 结论 | 旧 | 新 | 变化 |
|---|---|---|---|
| 一致报 NR | 10 | 18 | **+8** |
| 值一致 | 74 | 69 | −5 |
| 值不同 | 67 | 66 | −1 |
| **漏抽** | 10 | **16** | **+6** |
| **过度填充** | 19 | **11** | **−8** |
| 直观正确率 | 46.7% | 48.3% | **+1.6 点** |

**读法**：那条"定性描述不要硬填"的硬约束**确实生效**（过度填充 −8、一致报 NR +8），
但它同时把一部分"本来是模糊地带"的条目推向了漏抽（+6）。
**净 +1.6 点，在 180 条的样本上落仍在噪声内**——不能声称提分。

> 要下定论需要更大样本（至少全量一年 + 对照）。这里如实标注为**未定**。

## 7. 单位归一化的真实收益：确定性判定

这是"便于后期转换对比"的落点，且**不需要再跑 LLM 就能测**（`tools/_unit_judge_coverage.mjs`）：

| 指标 | 数值 |
|---|---|
| 可比较条目（两边都非哨兵） | 844 |
| **确定性判定的** | **433（51.3%）** |
| ├ 换算后同量（`identical`） | 231 |
| └ 数字相同、单位写法不同（`same_meaning`） | 202 |
| 仍需 LLM 语义判定 | 411（48.7%） |

**收益有两层**：
1. **省钱**：这类字段原本 47%/44% 的条目前缀都要走 LLM；
2. **更稳**（更重要）：LLM 判定本身有噪声——实测同一组 `"30"` vs `"30 minutes"`，
   在不同条目上被判过 1.0 也判过 0.5；`quantityEqual` 的结果**可复现、可审计**。

## 8. 后续建议

| 优先级 | 事项 | 依据 |
|---|---|---|
| 1 | **请医生确认 §5 的单位编码异常**（2020 年后 44 条"周→code 2"） | 影响该列 36% 的记录能否计分 |
| 2 | 用**全量一年**重做 A/B，确认提示词改动是净正还是中性 | 当前 180 条样本不足 |
| 3 | 针对**过度填充**再收紧：`最长随访` 的单位列过度填充 79 条，可加"该列最常为 NR"的字段级提示 | §3 |
| 4 | 针对**漏抽**（600 条，17%）做字段级定位提示 | `docs/14` 的裁定 |
