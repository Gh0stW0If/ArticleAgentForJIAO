## 3. 当前水平（2015 六篇，评测时间见 `build/eval/2015.json` 的 `at`）

```
6/6 篇成功 ｜ 证据不变量违规 0 处 ｜ 无截断、无 JSON 解析失败
```

| 工作表 | 准确率 | 命中 | 错 | 漏 | 多 |
|---|---|---|---|---|---|
| Sheet1（文章级 + 比较组） | **69.0%**（470/681） | 470 | 211 | 0 | 11 |
| Sheet2（结局分类） | **75.0%**（30/40） | 19 严格 + 11 语义 | 0 | 0 | 0 |
| Sheet3（结局 × 时点） | **72.5%**（477/658） | 436 | 106 | 52 | **655** |
| **合计（三表聚合）** | **67.9%**（936/1379） | 936 | 317 | 52 | 666 |

口径：`准确率 =（命中 + 编码命中）/（命中 + 编码命中 + 错 + 漏）`；「多」不计入分母，单列。
（三表聚合的命中数 936 = 470 + 30 + 436；聚合值**低于**各表分别报告值，因为三表分母权重不同。）

语义判定口径（Sheet2/Sheet3 自然语言字段）：

- 进入 2015 评分报告的 **85 组**：完全一致 21 ｜ 含义一致 27 ｜ 包含正确信息 8 ｜ 存在错误 8 ｜ 完全不一致 21
  → 加权（1/1/0.5/0/0）**61.2%**；完全一致 + 含义一致 = **56.5%**。
- `build/judge-report.md` 另存跨轮累计的 **109 组**（含 24 组「多」（有抽取、无金标准））：
  完全一致 13 ｜ 含义一致 34 ｜ 包含正确信息 13 ｜ 存在错误 13 ｜ 完全不一致 36 → 加权 **53.2%**。
  两组数字口径不同（是否含「多」），比较时须注明用的是哪一份。

**结论：Sheet1/Sheet2 已接近可用；Sheet3 的短板不是「抽错」而是「抽多」（655）与「漏」（52）。**

## 4. 路线图

### P1 — 把账对齐（评测可信化）

**问题**：目前只有 2015 年可评分。全局检出 **306 处**金标准异常
（编码超取值表 99 / code 列写成自由文本 68 / **值未在论文中出现 46** / 数值列写成散文 22 …），
2015 年恰好 0 处——所以 2015 的分数可信，**其余年份的分母是脏的，不能直接报数**。

| 事项 | 交付物 |
|---|---|
| 修复 Crossref `HTTP 400`（`resolveAndVerify` 的请求参数 / `mailto`） | 6 篇返回 `match` 或明确的 `unverifiable`，而非统一 400 |
| 对 2016–2025 逐年跑 `pnpm gold:anomalies` + `gold:row-anomalies` + `gold:vs-paper` | 每年一份「不参与评分」清单，逐条可追溯到证据 |
| 交叉核对金标准列错位（68 + 22 处） | 给源表维护者的逐单元格修订建议（不改 `Datas/`） |
| 按年报告口径一致性 | 每年：可评分字段数 / 被排除数 / 被排除原因分布 |

**验收**：11 个年份各有可复现的评测报告；被排除项 100% 有证据；评测输出显式打印被排除条目。

## 5. 依赖与里程碑顺序

```
P1 把账对齐 ──▶ P2 补架构缺口 ──▶ P3 全量抽取 ──▶ P4 消融与交付
   （评测可信）      （改动可控）        （规模可用）      （结论可信）
        │                                    ▲
        └── Crossref 修复可并行；前端筛选视图可随 P3 并行 ──┘
```

P1 必须先行：**在脏分母上比较各年份准确率会得出错误结论。**
P2 与 P1 可部分并行（编排器、文档修订不依赖评测口径）。

## 6. 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| Crossref 持续 400 | 元信息无法外部核验（当前降级为「未校验」，不影响其它字段） | P1 优先修复；修复前在响应里显式标注，不静默 |
| 金标准列错位（90 处） | 这些字段的得分无意义 | 排除评分 + 输出修订建议；不自动改数据 |

| 提示词规则持续变长 | 规则互相挤占（已发生过一次） | P4 消融，删掉无收益的规则 |

## 7. 明确不做的事（判断标准）

1. **不自动「修正」金标准** —— 数据里真实存在跨年份 ID 笔误等问题，自动改写会掩盖问题且不可审计。
2. **不过度拟合标注风格** —— 金标准自身写法不统一（同批既有 `VAS` 也有 `HDRS: 全称`），只能对齐主导形式。
3. **不反推无文本依据的取舍** —— 如「金标准为什么只收 RQLQ 的第 ③ 个域」。
4. **不用「整块当证据」兜底** —— 定位失败宁可留空，也不把块内无关内容算作证据。

> 遇到分歧时回到两条硬判据：
> ① 这个值能否在原文里找到？② 金标准自身是否自相矛盾 / 口径不一致？
> 二者都不成立时才认为流水线错了。
