# 全量运行与"给医生看的报告"

> 目标：在**全部年份**上跑「解析 → 抽取 → 评测」，统计每年份每张表的准确率，
> 记录疑似金标准问题与标准界定不清之处，产出一份**非技术**的讨论报告。

## 1. 几条命令

```bash
# ① 全量运行（解析 → 抽取 → 评测）。--follow 会等某年解析完再自动接手抽取，
#    不必人工盯着"哪年该跑第二步了"（实测这样最容易漏年份）。
node tools/run_all_years.mjs --follow --jobs 4

# ② 金标准排查（顺序不能反，见 §3）
pnpm gold:anomalies                       # 编码/取值与列取值表不符、列错位
pnpm gold:vs-paper -- --year 2015         # 取证：金标准的值在原文里找不到（需要该年已解析）
pnpm gold:evidence                        # 复核上一步的发现（不跑这步，评测的排除表会被误报污染，见 §3.1）

# ③ 生成报告
node tools/report_clinicians.mjs           # → build/report/医生讨论报告.md
```

`run_all_years.mjs` 的开关：`--years 2015,2016`、`--skip-parse`（已解析过）、
`--jobs N`（抽取并发，默认 4）、`--force-extract`、`--dry`（只打印计划）。

## 2. 规模与耗时（实测）

| 项 | 数量 | 说明 |
|---|---|---|
| 语料 PDF | **231** 篇（2015–2025） | `Datas/articles/<year>` |
| 金标准文章 | **224** 篇 | 2022/2023/2024 的少几篇（PDF 与工作簿行数不完全对应） |
| 单篇 MinerU 解析 | **61 s**（含模型加载） | 整年目录一次提交，模型只加载一次，后续篇明显更快 |
| 单篇 LLM 抽取 | ~20 次请求 | 并发 4 路时全量约 1.5~2.5 小时 |

即全量一轮大致 **2~4 小时**（单 GPU + 单 API key）。中间产物都在 `build/` 下，
重复运行会命中缓存，**中断后重跑不会重头再来**。

## 3. ⚠️ 工具执行顺序：gold:anomalies → gold:vs-paper → **gold:evidence** → eval

金标准排查工具都写同一个文件 `build/gold_anomalies.json`：

- `gold_anomalies.mjs`：按列取值表检查编码是否合规（覆盖全 11 年，不需要解析产物）；
- `gold_vs_paper.mjs`：取证式审计——金标准的数值在原文里**逐字找不到**（需要该年已解析）；
- `gold_evidence_check.mjs`：**复核上一步的发现**（写 `build/gold_evidence_check.json`）。

实测踩到的坑：`gold_anomalies.mjs` 原本是**覆盖**写入，重跑一次就把 `gold_vs_paper`
的发现**静默冲掉**——2015 年那 46 条取证发现消失，该年 Sheet3 准确率从 72.5% 掉到 70.9%
（排除项没了，本该剔除的错位值又回到分母里）。现已改为**合并写入**（去重键含 reason），
但顺序仍建议：**先跑基础排查，再跑取证审计，最后再评测**，否则评测用的排除表是旧的。

### 3.1 ⚠️ `gold_vs_paper` 的发现必须先复核（gold:evidence）

`gold_vs_paper` 的判据是"数值的字面形态能不能在原文里**逐字**找到"，**偏严**：
论文里写 `week 24`（而不是 `24 weeks`）、`24-week`、欧式逗号小数点 `46,67`、
排版把小数点吃掉、全角数字，都会判成"找不到"。

实测全量 1966 条这类发现，用宽容写法（数字与单位可前后调换、去小数点、去千分位、
统一 Unicode 减号与全角数字、逐位数字兜底）复核后：

| 复核结论 | 条数 | 处置 |
|---|---|---|
| 复核后**能在原文里找到**（检索误报） | 712 | **不作为问题**，也不进排除表 |
| 逐位数字能找到、写法可疑 | 756 | 不进排除表，报告 §4.3 单列供参考 |
| 连逐位数字都找不到 | 452 | 才作为"疑似金标准错"，进排除表 |
| 该篇没有解析产物，无法复核 | 46（全在 2015） | 按原判据进排除表 |

必须复核的原因：这些发现会直接进 `llm_eval` 的排除表，**排除错了等于把该扣的分抹掉**。
实测 2024 年 487 条里有 250 条其实能在原文里找到，恢复计分后该年 Sheet3 从 23.5% 变到 24.6%
——数字会往两个方向失真，不是单方向虚高。

因此 `llm_eval.mjs` 现在会读 `build/gold_evidence_check.json`：只排除
`strong`（连逐位数字都找不到）与 `unknown`（该篇无解析产物，无法复核），
`found`/`weak` 一律**不排除**；复核文件缺失时退回原行为并在控制台告警。

## 4. 报告内容与口径

`build/report/医生讨论报告.md`，六个部分：

| 章节 | 内容 |
|---|---|
| 一、覆盖范围 | 每年语料/金标准/已完成提取/已比对的篇数 |
| 二、准确率 | 按年份 × 三张表（Sheet1 研究信息 / Sheet2 结局分类 / Sheet3 结局数值），附数值类单列 |
| 三、判定口径 | 什么算"对"：编码严格比对、数值允许写法差异、描述类由语义判定四级分档 |
| 四、疑似金标准问题 | ① 值与编码对不上（按类型归纳 + 逐条清单）② 整行归属可疑（串篇） |
| 五、需要拍板的标准 | 逐条给"现状 → 疑问 → 可选口径"（条数见生成时的控制台输出，会随比对进展增加） |
| 六、方法附录 | 一页说清解析/提取/复核/联网核验怎么做，便于非技术读者判断可信度 |

写作原则（面向临床研究者）：不出现 prompt/JSON/缓存这类实现细节；
每条结论都带**可核对的例子**（哪篇、哪个结局、金标准填了什么）；
需要医生决定的地方给"现状 → 疑问 → 选项"，而不是只报错；
**凡提到具体字段，一律同时给"原始表格列名（含列字母）"与"提取用字段名"**——
只写 `end_of_treatment.binary.n` 这种内部键，医生没法对着自己的工作簿看。
实现见 `tools/lib/field_labels.mjs`：列名与列号直接取自 `build/gold/<year>.json` 的
`column_map` / `field_definitions`（那本身就是从原始 xlsx 读出来的，不是另起的名字）。
覆盖 §2.1、§2.1.1、§2.3、§4.1、§4.3 的表格，以及 §5 里每一条涉及的列。

## 5. 报告里最需要医生看的两节

**§4 疑似金标准问题**：全量 11 年累计 **2356 条记录**，去重后约 **630 个问题**，分六类：

1. **该值在原文里找不到**（最多，279）：连"逐位数字"都在原文里找不到——需确认是原文表述不同，
   还是这个值来自别处（另外 974 条的同类记录被 §3.1 的复核判为"其实在文中/写法可疑"，不计入问题）；
2. **编码不在允许取值内**（149）：某列文档里只有几个编码，金标准填了表外的数字；
3. **影响因子与 2019 年 JCR 表不一致**（124）：以 `Datas/IF-SCI-2019.xlsx` 为准，见 `docs/12-impact-factor.md`；
4. **编码列里写成了文字**（72）：如把"最差情况分析"写进应当填数字的格子（疑似整列错位）；
5. **金标准的期刊名本身有问题**（6）：影响因子无从核对；
6. **整行归属可疑**（2）：结局名称在该篇论文里完全找不到（如 2015-06 名下的
   「2.maximum anxiety」实属 2015-05，金标准自带的文献编号也指向 2015-05）。

这些**已从准确率统计中剔除**，只记录、不扣分，请医生逐条确认是"金标准要改"还是"机器理解错"。
报告 §4.3 另列"写法可疑"的一组，**没有**从统计中剔除，仅供核对具体论文时参考。

**§5 标准界定不清**：条目数由生成时的控制台输出给出（不要在本文件里写死，会过期）。最关键的几条：

- **例数口径**：同一篇里"疗程结束"取完成治疗的例数、"随访"取随机化例数，两个数原文都有；
- **效应量取 ITT 还是符合方案集**；
- **变异值 vs 95%CI**：工作簿"变异值下限/上限"两列装的是离散度（SD 时只填下限），
  且"变异值类型"出现过多选（`3/2`）与批注"只选 1 个"矛盾；
- **组间差值什么时候记**；
- **结局行粒度**：比较组是否限定"试验组 vs 对照组"（三臂试验出现过"对照 vs 对照"）；
- **量表分域要不要单独成行**（RQLQ(S) 只收录了一个域）；
- **多张分析表取哪张**（主要分析 / 敏感性分析 / 符合方案集）；
- **分类编码口径**（SF-12 归"功能"还是"生活质量"；BDI 归"精神"还是"肌骨"）；
- **列含义与填写不一致**：如"刺激强度"列里填的是留针时间、"得气"列里填的是穴位深度，
  需要对着工作簿确认是串列还是取值表更长。

## 6. 未完成时的续跑

全量一轮要几小时，中途结束后直接重跑同一命令即可：

```bash
node tools/run_all_years.mjs --follow --jobs 4   # 幂等：已有产物的年份会跳过
node tools/report_clinicians.mjs                 # 报告按已有评测结果生成，缺的年份不列
```

报告里"一、覆盖范围"会把**未完成的年份**明确标出来，不会把"没跑到"混进准确率。

## 7. 实测发现的"漏做"（不是判断分歧）

报告 §2.1.1 专门列一类字段：**金标准有值、机器一处都没抽到**（`hit + code-hit + wrong == 0`）。
这类与"抽错"性质不同——不涉及口径分歧，只是"这一格我们没做"，补齐即可。
最近一次全量（11 年）实测有这些：

| 字段 | 规模（已比对年份合计） | 成因 |
|---|---|---|
| `end_of_treatment.binary.n` | 89 处 | 二分类（事件）结局里，模型只输出事件数 `events`，**不输出每组的例数 `n`** |
| `study.remarks` | 52 处 | Sheet2「备注」列**提示词里没有这个字段**（金标准此列实测全部写 `NR`） |
| `follow_up_end.binary.n` / `baseline.binary.n` | 12 / 8 处 | 同上（随访、基线时点） |
| `baseline.binary.difference_estimate` 等三键 | 11 / 11 / 6 处 | 基线时点的"组间差值"——基线本不该有疗效差，**先确认金标准此处该不该填** |
| `baseline.binary.events` / `follow_up_end.binary.events` | 6 / 4 处 | 基线与随访的事件数基本没抽 |
| `*_end.binary.rr` / `rr_ci_lower` / `rr_ci_upper` | 各 1~2 处 | RR 及其区间没做（`or` 同理） |

> 这张表的数字**随语料增长会变**（多比对一年就会变多），以报告 §2.1.1 的实时输出为准。

两点必须写清楚，否则会被误读：

1. **`study.remarks` 是"约定"问题不是"能力"问题**：已比对年份里金标准这一列
   **全部**是 `NR`（无一条真正备注）。机器只要照填 `NR` 就对上了。
   报告 §5.19 因此单列一条待拍板：**"论文未报告"是否一律显式填 `NR`**（还是留空等价）。
2. **`.binary.n` 的路径是评测器摊平后的写法**：金标准结构是
   `timepoints.<时点>.binary.experimental.n`（每组嵌套），评测器递归时不延长作用域，
   于是按 `end_of_treatment.binary.n` 记账。看到该键不必去金标准里找同名的扁平字段。

> 评测口径上的一个细节：`judged.<...>` 前缀的键是**语义判定**（自然语言字段）那一类的记账，
> 与严格字符匹配的 `<时点>.<块>.<字段>` 不是同一套分数，报告里始终并列给出，不合并。

## 8. 低准确率文章怎么查（见 `docs/11-low-accuracy-analysis.md`）

| 命令 | 用途 |
|---|---|
| `pnpm diagnose:low` | 语料级失分构成 + 最低分文章的"主因/辅因"清单 |
| `pnpm diagnose:low -- --article 2024-12` | 单篇的全部故障信号（结构/材料/证据/数值/编码/解析） |
| `pnpm judge:cmp-desc -- --n 240` | 抽样语义判定**比较组描述性字段**，量化"严格匹配低估了多少分" |
| `pnpm judge:article-desc` | 同上，针对**文章级（metadata）**描述性字段 |
| `pnpm metadata:fields` | metadata 逐字段"错在哪"拆解（逐字同 / 去标点同 / 写法近似 / 明显不同 / 没填） |
| `pnpm metadata:ceiling` | metadata 能否到 90% 的四口径测算 → `build/metadata_ceiling.json` |
| `pnpm if:index` / `if:gaps` / `if:gold` | 影响因子查表索引 / 列出表里查不到的刊 / 记录与表冲突的金标准值（见 `docs/12-impact-factor.md`） |
| `pnpm gold:timepoints` | 金标准**时点归属**可疑检测：某行只有基线块有组间差值、后续时点全空（2023-27 那 40 个值就是这么查出来的） |
| `pnpm parse:health` | 空表 + **正文过短** + **同名撞车目录**（下文第 2 点） |

### 8.1 解析质量与改动效果（新增，见 `docs/13`、`docs/14`）

| 命令 | 用途 |
|---|---|
| `pnpm latex:noise` | MinerU **公式误触发**污染面：多少篇/多少表的数字被写成 `4 1 . 7 5`（实测 180/224 篇） |
| `pnpm latex:shapes` | `<eq>` 片段的形态骨架统计（用于安全地设计去 LaTeX 规则） |
| `pnpm latex:impact` | 上述污染**打中多少金标准数值**（实测 223/6,874 = 3.24%，67 篇）→ `build/latex_value_impact.json` |
| `pnpm fidelity` | MinerU × PDF 原生文字（PyMuPDF）**数值对账**，篇级/页级/表级三口径 → `build/table_fidelity.json` |
| `pnpm fidelity:raw` | 同上，但用 MinerU **未清洗**的原始输出（对照用） |
| `pnpm ab:fields` | **定向 A/B**：只看"修复前材料里读不出来"的金标准字段，新旧抽取各答了什么 |
| `pnpm ab:eval` | 两份 `build/eval/<year>.json` 的**全量前后对照**（作用域 / Sheet / 字段 / 逐篇） |

> `ab:eval` 与 `ab:fields` 解决的是同一个痛点：评测报告每次都会被覆盖，
> 改完就看不出差别。**任何"优化"都要先留一份旧 eval 再重跑**，否则结论只能靠印象。

三个已确认的坑：

1. **同名 `.jpg` 顶掉 `.pdf` 的解析**：`Datas/articles/2023/` 里同时有 `2023-19.pdf`（9 页正文）
   和 `2023-19.jpg`（图版），MinerU 按输入主名建目录 → 图版占了 `<id>`、正文被写到 `<id>_2`。
   只认 `<id>` 会让整篇拿一张图去抽取（实测 2023-19 = 0.0%、2025-07 = 1.6%）。
   已修：`findMiddleFile` 收集 `<id>`/`<id>_2`/… 全部候选，按页数→正文长度取最完整的一份。
2. **`--only` 会覆盖整年评测报告**：`llm_eval --year 2023 --only 2023-19` 曾把
   `build/eval/2023.json` 写成只含这一篇的小报告，而 `report_clinicians.mjs` 正是按年统计的。
   已改为写 `build/eval/<year>-only.json`。
3. **同篇附件被当成独立文章、覆盖正文产物**（2024-12 = 全语料最低分 5.1% 的真因）：
   `Datas/articles/2024/` 里的 `2024-12-01.pdf`…`2024-12-04.pdf`（各 1 页附件）被旧
   `listStudies()` 当成独立研究，而 `articleIdOf('2024-12-01') = '2024-12'` → 四次附件运行
   **都写进正文的产物文件**，排序上附件在后 → 附件赢。产物的证据只剩第 1 页 3 个块，
   结局计划拿到的材料只有 310 字符（正文那次 13,523 字符）→ 模型老实回答"没有结局声明"
   → `outcomePlan.outcomes = []`。
   已修：`@aa/core` 新增 `studiesFromPdfNames()`（只认整串 `YYYY-N` 的正文 PDF，
   附件记入 `skipped`），`llm_run.mjs` 与 `apps/web/server.mjs` 都改用它；
   `llm_run.mjs` 另加护栏：`studyId !== doc.articleId` 时**拒绝写入**并报错。
   校验：过滤后每年正文 PDF 数 == 金标准篇数（224 == 224）。
   2024-12 修复后 5.1% → 11.6%，2024 年 Sheet1 52.7% → 53.1%、Sheet3 24.6% → 25.3%。
   详见 `docs/11-low-accuracy-analysis.md` §3.2。
