# 细节字段该"让 LLM 更细查找"还是"新增 SKILL"？

> 问题：方案细节（干预频次、留针时间、分配隐藏、基线连续量、CI 等）抽不出来时，
> 是该把提示词写细、让模型在**同一份材料**里再找一遍，还是**加一个 SKILL**？
> 本文给出判据、证据与逐项裁定，避免"感觉该加个 SKILL 了"这种决策。

## 0. 一句话结论

**先把"更细查找"做完，全流程只在一处新增 SKILL（表格列角色定位），另外两处应该写确定性代码。**

理由：诊断数据显示，失分的主因**不是"步骤不够"，而是"材料里有、模型没写"**——
加 SKILL 并不能让模型看到它本来就没看的段落。

## 1. 判据：什么情况下新增 SKILL 才划算

一个新 SKILL 只有在满足下面**至少一条**时才值得加（否则就是在给同一条流水线加税：
每次运行都多一次请求、多一份可能出错的地方、多一处要维护的提示词）：

| 判据 | 含义 | 反例（不满足 → 别加 SKILL） |
|---|---|---|
| **(a) 材料视图不同** | 这一步需要一份**现有 SKILL 拿不到的材料切片**（例如"只要表头行"、"只要流程图"、"只要首页版式"） | 只是要在同一份材料里**再找一遍** → 加提示词规则就够 |
| **(b) 中间产物可复核** | 这一步会产出一个**结构化中间结果**（列角色映射、结局别名表……），能让后面的错误可定位、可缓存、可人工复核 | 只是一次性的判断，没有可复用的中间产物 → 加提示词规则就够 |
| **(c) 规则是确定的** | 换算、匹配、格式规整这类有明确规则的事 | **一律用代码，不要用 LLM**：LLM 在这里只会引入不确定性 |

## 2. 证据：失分到底卡在哪一步

### 2.1 "材料里有、模型没写"占近一半（`tools/materials_coverage.mjs`）

对 550 组"机器填了 NR/空"的描述性字段，把两个 SKILL 的材料按**线上完全相同的参数**重建，
再查金标准答案的特征词在不在材料里：

| 结论 | 占比 | 该改哪里 |
|---|---|---|
| 答案**就在该 SKILL 自己的材料里** | **45%** | 提示词（召回） |
| 只在**另一份**材料里 | 2% | 材料覆盖 |
| 两份都没有，但**全文里有** | **4%** | 材料覆盖 |
| 全文里也没有 | 7% | 金标准/改写问题 |
| 值太短无法判定 | 41% | 判分口径 |

即：**47% 是"材料给了但模型没写"，只有 4% 是真的没喂材料**（≤60 字符的短值另有 41% 无法判定）。
往"材料覆盖"上使的劲，最多只能碰到 4+2=6%。

### 2.2 失分构成（Sheet1）

- 按类型：**编码 42% / 描述 43% / 数值 15%**；
- 按层级：比较组级占 Sheet1 字段 84%、占失分 **89%**；
- 最差字段**全是描述类**：治疗频次描述 9.5%、随机序列产生方法 9.9%、干预方法名称 10.2%、
  对照组名称 14.3%、最长随访描述 21.6%、分配隐藏 31.6%、疗程 32.0%。

描述类字段的答案几乎都是**方法学段落里的一两句话**——它们就在材料里（comparison 的
材料覆盖 `methods`/`results`/`abstract` 且表格不随章节过滤），缺的是"逐字段回头确认"。

### 2.3 Sheet3 的失分**不是字段读错**，是"结局行对不上"

- 金标准结局行 1,110 条：配上 766，**没配上 344（31%）**；
- Sheet3 全部"漏" 10,909 个字段里，**9,250 个（85%）来自这些没配上的整行**；
- 真正"行配上了、字段没抽到"的只有 1,659 个（15%）。

这是**对齐/粒度**问题（同一量表在同一篇里被拆成多行、多域或多分量表），
规则明确、可枚举 → **属于判据 (c)，应该写确定性代码**，不是加 SKILL。

### 2.4 反例警示：材料洗干净了，分数没动

`docs/13-mineru-latex-noise.md` 记录了一次完整 A/B：把 MinerU 的 LaTeX 污染
（80.4% 的论文、82.2% 的 `<eq>` 片段把数字写成 `4 1 . 7 5`）从材料里彻底清掉，
篇级数值一致率 90.55% → 93.19%、材料噪声数字 −86%，
但**评测分数 76.2% → 75.7%（−0.52 点，落在噪声内）**——因为模型自己能重组那些数字。

**教训**：改动"材料质量"不一定动分数。判断"该不该加 SKILL"时，
必须先用 `materials_coverage` 这类工具确认**瓶颈在不在"模型没看到"**，
而不是凭"材料看着更干净了"就以为会提分。

## 3. 逐项裁定

| 候选方案 | 类型 | 裁定 | 依据 |
|---|---|---|---|
| 字段级检查清单 + "写完回头再查一遍"规则 | 提示词 | ✅ **优先做** | 47% 的 NR 描述字段答案就在材料里（§2.1）；最差字段全是描述类（§2.2） |
| 数值归一化口径 + 证据留原文（第③问） | 提示词 | ✅ **已做** | 7 份提示词生效；`quote` 逐字命中 99.0%~99.8%（§4） |
| **表格列角色定位**：先输出"这一列是什么统计量"的映射，再据此取值 | **新 SKILL** | ✅ **唯一值得加的** | 同时满足 (a)+(b)：需要"只看表头/表注"的材料视图；产出可复核的**列角色映射**。受影响字段全是表格里的基线连续量与 CI |
| 结局行对齐（同一量表拆成多行） | 确定性代码 | ❌ 不该用 LLM | §2.3：85% 的 Sheet3 失分来自行对不上，规则可写死 |
| 单位换算（min↔h、cm↔mm） | 确定性代码 | ❌ 不需要 LLM | 规则明确；且金标准按**原文口径**记录，换算了反而不一致 |
| 全字段"再来一遍"的自检 SKILL | 新 SKILL | ⚠️ 与现有 `outcome-audit` 重复 | 已有审计步骤在做同一件事 |

## 4. 已落地的改动与读数

`tools/prompt_gen.mjs` 公共规则新增 **4b「数值归一化口径」**（详见 `docs/13` §10），
并给 `packages/skills/src/grounding.ts` 加了 `groundingStats` 埋点，
`tools/llm_run.mjs` 汇总里直接打印：

```
quote 定位：逐字命中 479/480（99.8%） | 降级 1 | 定位失败丢字段 0 | 无 quote 0
quote 定位：逐字命中 497/502（99.0%） | 降级 5 | 定位失败丢字段 0 | 无 quote 0
quote 定位：逐字命中 406/408（99.5%） | 降级 0 | 定位失败丢字段 2 | 无 quote 0
quote 定位：逐字命中 1365/1374（99.3%） | 降级 3 | 定位失败丢字段 6 | 无 quote 0
```

- `exact` = 整串逐字命中（提示词要争取的）；
- `degraded*` = 模型回传了"更规范"的版本，靠降级窗口救回；
- `notFound` = 三种都失败 → **整个字段被丢弃**（真正的损失，实测 0~6 个）。

读数说明"值归一化 + 证据留原文"这条规则**模型听得进去**，没有把 quote 一起归一化掉。

## 5. 后续建议（按性价比排序）

1. **补"字段级召回"提示词**：为 Sheet1 里准确率最低的 12 个描述字段各写一条
   定位提示（"这类信息通常写在方法学第几段/表注里，找不到再填 NR"）。
   依据：这些字段的答案 45% 就在材料里。清单、归属 SKILL 与提示词行号见
   `docs/15-field-skill-trace.md`（**注意**：早先那版"12 个 <35% 的描述字段"是错的，
   来自 `sheet1_fields.mjs` 漏掉 `judged.*` 键 + 把数值字段错判成描述类，已在 `docs/15` §0 更正）。
2. **给比较组级材料加"表注 + 表格全量"**：`materials_gap` 显示部分字段的答案在
   表格 footnote 里，而 footnote 目前只随 `text` 走，容易被裁剪顺序丢掉。
3. **表格列角色定位 SKILL**（唯一新增项）：中间产物 = 列角色映射表，可复核、可缓存。
4. **结局行对齐改成确定性代码**：先用规则（量表名归一 + 分值/分量表后缀）做候选匹配，
   只把**规则拿不准的**交给 LLM 判——把 344 行没配上的问题从"模型自由发挥"降级为"规则覆盖"。
