# 27 · 全流程操作教学视频大纲（分镜脚本）

> 这份是**录制脚本**，不是功能说明。每一段都给：时长、屏幕上放什么、手往哪点、
> 口播要说什么、以及**录制时容易翻车的地方**。
> 功能细节见 `docs/26`，界面结构见 `docs/27` 之外的 README。

---

## 〇、开拍前先定三件事

### 0.1 观众是谁 → 决定录哪几条

同一套操作，观众不同，深度差一倍。**先定，别录完再剪**：

| 成片 | 观众 | 建议时长 | 段落 |
|---|---|---|---|
| **A · 医生/核对人版** | 实际做核对的人 | **25–30 min** | 第 1–9 段 |
| **B · 学生/维护者版** | 接手维护、跑评测、打包的人 | **15–20 min** | 第 1–3 段（快进）+ 第 10–11 段 |
| **C · 完整版** | 交付/答辩用 | **40–45 min** | 1–11 全录，第 4 段是主体 |

> 建议：**先录 A**（最刚需），B 用 A 的素材剪 + 补录第 10–11 段。

### 0.2 素材准备（录之前必须跑通，别现场等）

- **演示用文章**：固定一篇，全文里同时有**数值型结局**和**量表型结局**
  （比如 `2015-01`：fibromyalgia / 抑郁 / 生活质量），这样四类操作都能演到。
- **必须提前准备好的"人工错误"素材**：
  1. 一个**值写错**的字段（演「编辑」）
  2. 一个**位置对但值不对**的数值（演「定位证据」发现机器抄错行）
  3. 一篇**有待人工裁定行**的研究（`2015-06` 有 1 条；`2025-01` 有 4 条）——否则第 4.8 段没东西可演
  4. 一份**已核对过**的覆盖层（演「多人分歧」要有第二个核对人）
- **一份"已导出的表 + 改过两格"的文件**：第 7 段导回用，现场改太慢。

### 0.3 录制环境

| 项 | 建议 | 原因 |
|---|---|---|
| 分辨率 | 1920×1080，浏览器 100% | 界面最小字号 10.5px，缩放后看不清 |
| 界面字体档位 | **中档（100%）** 全程不动 | 切档位会让画面跳动，且第 4 段要框选，坐标观感要稳定 |
| 鼠标 | 开**高亮/放大光标** | 观众要看清点哪里 |
| 通知 | 关掉微信/邮件弹窗 | 会被录进去 |
| 数据现场 | 先跑一遍完整流程，再**清掉本次产生的覆盖层** | 否则演示"第一次核对"时界面上已经有记录了 |

## 第 1 段 · 认识它（1.5 min）

**目标**：观众知道这是个"**把论文里的数据抽出来、由人来核对**"的工具，以及它的边界。

| 镜头 | 操作 | 口播要点 |
|---|---|---|
| 界面全景 | 打开 http://127.0.0.1:43130（或双击便携版 exe） | "左边是论文原文，右边是抽出来的字段，**中间靠证据连着**" |
| 指三块区域 | 顶栏 / 左 PDF / 右字段 | "顶上选文章和跑任务，左边看原文，右边核对" |
| 指选项卡 | Sheet1 / Sheet2 / Sheet3 | "右边这三张选项卡，就是**医生那张 Excel 的三张表**——文章级、结局分类、结局×时点" |

**必须说的一句**：
> "机器的结果**不是最终稿**，所有值都要人核对过才算数；有分歧的地方，工具**不会替你选**。"

**坑**：别一上来就讲准确率数字。医生关心的是"能不能用、要花多少时间"。

## 第 2 段 · 启动与设置（2.5 min）

### 2.1 两种启动方式

| 方式 | 操作 | 适合谁 |
|---|---|---|
| **便携版**（推荐给医生） | 双击 `ArticleAgent-0.1.0-portable.exe`，自动打开界面 | 医生；**不用装 Node** |
| 源码启动（给维护者） | `corepack pnpm web:api` → 浏览器开 `http://127.0.0.1:43130` | 开发/调试 |

> ⚠️ 口播提醒维护者：本仓库的 `pnpm` 不在 PATH 上，要写 **`corepack pnpm …`**，
> 直接 `pnpm …` 会报 `'pnpm' is not recognized`。

### 2.2 设置对话框（点右上角「设置」）

按顺序演四件事：

1. **界面字体**：小 / 中 / 大 → "字太小可以调，**立即生效、本机记住**"
2. **API 配置**：Base URL / 模型 / **API Key**（`sk-…`）
   - 关键演示：已有 key 时**只显示掩码**（`sk-****1234`），输入框留空 = 不修改
   - "密钥只存在本机 `runtime/llm.local.json`，**不会上传、不会进仓库**"
3. **测试连接** → 点一下，出现"连通"结果
4. **Crossref mailto**：填邮箱 → "用来联网核对文章元信息（DOI/期刊/年份），Crossref 要求带邮箱"

**常见坑（要主动讲）**：
- 如果 key 来自环境变量 `DEEPSEEK_API_KEY`，界面上会标注"改这里不生效"
- 保存后 `temperature` / `maxTokens` 一般不用动 —— 别在现场乱改

## 第 3 段 · 导入 → 解析 → 抽取（3 min）

**这一段是"等机器"，节奏要快，重点是让观众知道各要多久、产物在哪。**

### 3.1 导入文章（20 s）

- 点顶栏「**导入文章**」→ 选 PDF
- 口播："导入的件放在 `build/imports/`，**不混进只读语料 `Datas/`**，
  旁边存一份 `.meta.json` 记原始文件名和 sha256，方便追溯"
- 研究下拉里会出现它，带「（导入）」标记

### 3.2 解析（1 min）

- 点「**解析**」→ 任务条出现「MinerU 解析进行中（job id）… 已 Ns」
- 点「展开日志」→ 让观众看一眼日志长什么样（**不要念日志**）
- 口播："这一步把 PDF 拆成**带坐标的文本块**——后面所有'定位证据'都靠它"
- 产物：`build/mineru/<year>/<id>/`

### 3.3 抽取（1.5 min）

- 点「**抽取**」→ 任务条变「LLM 抽取进行中」
- 口播两个预期管理：
  - "**单篇几分钟**；跑一整年（200 多篇）要几小时，通常后台跑"
  - "抽取会花 API 费用"
- 完成后点「**刷新字段**」→ 右侧出现三张选项卡的字段
- 产物：`build/extraction/<year>/<id>.json`

**坑**：
- 抽取中**别点别的按钮**（按钮是 disabled 的，点了没反应会让观众以为卡了）
- 如果现场网络慢，**提前录好这段**，后期加速 4×，右上角打"加速中"

## 第 4 段 · 人工核对（主体，12–15 min）

> **这是全片的重点，占一半时长。**建议拆成 8 个小节，每节一个明确动作。

### 4.0 先把三件事讲清（1 min）

| 概念 | 一句话 |
|---|---|
| **字段** | 右边每一行 = 原表里的**一个格子** |
| **证据** | 每个机器值都带"从原文哪里抄的"（页码 + 框） |
| **核对人** | 右上角填名字，**填了才能提交**（"未设置，暂不能提交"） |

- 演一次：核对人输入框填 `张三` → 回车
- 口播："**一位核对人一份记录**，互不覆盖——所以可以两个人独立做，不会打架"

### 4.1 字段按原表列序排（30 s）

- 点开 Sheet1，「文章级字段（按原表列序）」
- 口播："顺序**就是医生那张 Excel 的列序**，不是随机排的——对着看不会串行"
- 指一下"原始列"这一栏："每一格都标了它在原表是哪一列"

### 4.2 点字段 → 在 PDF 上定位证据（1.5 min）

- **点任意一个字段** → 左边 PDF 自动跳到那一页，把证据框**高亮**
- 口播："这就是为什么不用担心机器乱抄——**点一下就能看到它抄的是哪里**"
- **重点演示**：找一个机器抄错行/抄错列的字段
  - "这里机器抄的是第 3 行，但论文里对应的是第 5 行"
  - 这为 4.3 的"编辑"做铺垫
- **顺便讲一个细节**（观众一定会问）：
  「**定位证据**」这个按钮有**两种行为**——
  - 该字段**已有**证据坐标 → 直接跳到那个框
  - 该字段**没有**坐标（比如你手工补的）→ 拿值去解析文本里**搜一遍**定位，
    按钮提示写着"只读，不写盘"
  > "机器没给坐标的格子，也能找到原文；但它**只跳过去给你看，不会自动写成证据**——
  > 要留下证据得用下面的『框选证据』。"

### 4.3 编辑 / 确认 / 回滚（2 min）

字段行上一共这几个按钮，逐个演：

| 动作 | 按钮 | 口播 |
|---|---|---|
| **编辑** | 「编辑」→ 改值 → 保存 | "改成对的，**改动会记在你名下**" |
| **确认无误** | 「确认无误」 | "机器抽对了，点一下确认——**确认也是有效记录**，汇总里能看出谁核了多少" |
| **回滚** | 「回滚」 | "改错了可以回滚到机器原值"（只在已改成人工时才出现） |

- 口播要点："右上角会变成 **人工 1 · 修改 1**，说明这一格有你的记录"

### 4.4 框选作证据（2 min）

> 这一节录**最出效果**，一定要慢。

1. 点某个字段的「**框选证据**」→ 该按钮变成「在 PDF 上拖框…」
2. 顶栏切到「**标注模式（框选=证据）**」
3. 面板顶部出现横幅："标注模式：在左侧 PDF 上拖拽框选，将作为 `<字段>` 的证据"
4. 在 PDF 上**拖一个框** → 松手 → 提示"已保存"
5. 切回「**浏览模式**」
6. 再点这个字段 → 高亮的就是**刚框的地方**

口播：
> "机器抄漏了、或者论文里那句话在别处，**你自己框一段**，
> 这段就变成这一格的证据——**以后谁看都能回到原文**。"

**另一个入口**：先在 PDF 上浏览、选中某段文字，字段行上会多出一个
「**用当前框选作证据**」按钮 —— 反过来用也行（先选原文，再挑字段）。

**坑**：
- 框选要**在页面内**、别拖到面板上
- 界面放大档位会影响坐标换算（已处理），但录像时**别中途切字体档位**

### 4.5 补字段（1 min）

- 滚到底部「**＋ 新增字段**」→ 填字段名 + 值 → 保存
- 口播："机器完全没抽到的格子，可以手工补一行"

### 4.6 Sheet3 的两组"候选"要分清（1.5 min）

> ⚠️ **这两组长得像但完全不同，是观众最容易混的地方，必须讲。**

| 分组 | 是什么 | 按钮 |
|---|---|---|
| **待人工确认纳入** | 流水线自己说"这个结局不属于那六类"（自报的候选） | 「纳入抽取」→ 提升为新结局行 |
| **待人工裁定：金标准没要的结局行** | 机器抽了、**但金标准里没有对应项** | 「保留 / 丢弃 / 撤销」 |

演「纳入抽取」：点一下 → 提示"已纳入为 Sheet3 结局 N" → 新行出现
口播："这是把机器犹豫的结局，正式提上来变成一行"

### 4.7 待人工裁定：决定留哪些结局（2.5 min）★ 新功能，重点

- 切到 Sheet3，指最上面的「**待人工裁定：金标准没要的结局行（N 条）**」
- 逐条看结构：
  - 结局名 / 测量工具
  - **N 个字段**
  - "**最接近的金标准行：「…」（名字相似 0.33、重合数值 2）**"
  - 按钮：**保留** / **丢弃** / **撤销**
- 演一遍：点「丢弃」→ 该行变灰 → 提示"结局行 N 已丢弃（记在「张三」名下）"
- 再点「撤销」→ 回到"未裁定"

**口播（这段是产品理念，要说透）**：
> "机器抽的结局通常**比金标准多**——论文里报告的结局有七八个，
> 医生那张表可能只收三个。多出来的这些，**工具不算它错**，而是列出来问你要不要。
> <br>注意这里给了「**最接近的金标准行**」：因为机器的匹配是按名字相似度算的，
> 有时候明明是同一个结局、只是叫法不同，也会被列进来。
> **所以最终判断在你，不在工具。**"
>
> "丢弃的行**不会出现在导出的表里**——这就是这个功能的实际作用。"

**坑**：
- 讲清"分歧时按**保留**处理"（删数据不可逆）
- 别把"丢弃"说成"删除数据"——**原始抽取产物一个字节都没动**，只是不进交付表

## 第 5 段 · 多人核对与分歧（4 min）

**目标**：让观众相信"两个人独立做，工具不会让谁覆盖谁"。

1. 指右上角「**核对 N/M**」按钮 → 展开「核对汇总」面板
2. 面板内容逐个指：
   - 核对人列表（`张三（12 条）、李四（9 条）`）
   - `一致 N · 仅一人 N · 分歧 N · 未核对 N`
   - **两两一致率**（"两个人共同核过的格子里，有多少一致"）
   - **待第三方仲裁** 列表
3. **演示分歧**：换核对人身份（把名字改成 `李四`）→ 对**同一格**给出**不同的值**
4. 指面板：

**口播（关键设计，一定要讲）**：
> "两个人不一致的时候，工具**不替你选**——保留机器原值，把它标成'分歧'，
> 等第三个人来仲裁。<br>
> 因为**专家的分歧本身就是最重要的信息**，替你们挑一个，这个信号就没了。"

5. 演"第三人仲裁"：以第三个人身份改成两边之一 → 状态变成"一致" → 生效

**坑**：切换核对人时提醒观众"**改动记在当时填的名字下**"，别录到一半忘了换回来。

## 第 6 段 · 导出（4 min）

### 6.1 单篇导出（1.5 min）

- 点「**导出 XLSX**」→ 下载 `人工核对_2015_2015-01_2026-09-25.xlsx`
- 打开（切到 Excel 录屏）逐个工作表讲：

| 工作表 | 内容 |
|---|---|
| **核对汇总** | 封面：范围/时间/核对人、字段总数、已核对、一致/分歧/仅一人、逐人工作量、两两一致率、待仲裁清单、**结局行裁定明细** |
| **Sheet1 / 2 / 3** | 每行一个字段：`工作表｜年份｜研究｜所在行｜字段｜原始列｜fieldPath｜机器值｜机器证据｜<核对人>·值｜·动作｜·备注｜核对状态｜采用值｜是否改动` |
| **签名** | 导出人 / 时间 / 范围 / 规模 + 校验和 |

- 指一下**有分歧的行整行标红**
- 口播："**每个字段一行**、**每位核对人三列**（值 / 动作 / 备注）"

### 6.2 批量导出（1 min）

- 点「**批量 ▾**」→ 弹窗四项：`{年} 年 XLSX / CSV`、`全部年份 XLSX / CSV`
- 口播："批量时每行多带 `年份`/`研究` 两列；**缺抽取产物的篇目会跳过并计数**，不会让整次导出失败"

### 6.3 XLSX vs CSV 怎么选（30 s）

| 格式 | 用途 |
|---|---|
| **XLSX** | 给人看/改：4 个工作表、分歧标红、签名单独一页 |
| **CSV** | 给程序/AI 读：三表拼成一张、带 UTF-8 BOM（Excel 打开不乱码）、签名放首行注释 |

### 6.4 署名（1 min）★ 必须讲清边界

- 指「签名」工作表
- 口播（**这段话别省，否则会被误当成防伪**）：
> "导出**必须署名**——导出人、时间、范围、规模都写进文件。
> 它解决的是**归属**：这份表是谁导出的、改动该记到谁名下。<br>
> ⚠️ **它不是防篡改签名**。文件本来就是要给人编辑的，
> 校验和只用来发现'签名块被表格软件改坏了'。"

## 第 7 段 · 线下修改 → 导回（5 min）

> **这是医生最常用的闭环**：导出 → 在 Excel 里核对 → 导回来。

1. 用一份事先改好的表（改了 2 格，其中 1 格清空）
2. 顶栏点「**导回…**」→ 弹出「人工核对工具 · 2015 / 2015-01」
3. 选文件 → 勾选「**把被清空的格子当作撤回**」的取舍要讲：
   - "默认**不勾**：清空有歧义，可能只是没填完"
4. 点「**预览差异**」→ 逐条念：`字段 | 原值 → 新值 | 动作`
5. 确认无误 → 点「**确认写入**」→ 提示写入条数
6. 回界面看：那两格已经变成"人工"状态

**三个要主动讲的点**：
- **默认 dry-run**："一定是**先预览、再写入**，不会一点就改"
- **只增改、默认不删**
- **动作是现算的**："按'值 vs 机器值'当场判断是确认还是修改，
  **不信文件里那份可能已经过期的快照**"
- **每次导回落一份批次快照**（`build/review-batches/`）→ 可追溯，也能当"两组对比"里的一组

### 7.1 署名校验（1 min）

演一次"署名对不上"：

- 把界面核对人改成和别人不一样的名字 → 点「确认写入」→ **被拒绝**
- 界面提示：这份文件是「A」导出的，但你以「B」身份导回
- 勾「**忽略署名异常**」→ 才放行

口播：
> "这是**故意的**——防止把改动记到别人名下。
> 生效身份由**文件署名**决定，不是你界面上随手填的名字。"

## 第 8 段 · 两组结果对比（2 min）

- 点「**对比…**」→ 选项卡「两组结果对比」
- 两个下拉：`机器` / `核对人:张三` / `核对人:李四` / `导入批次:<id>`
- 选 `机器` vs `核对人:张三` → 点「**运行对比**」
- 结果四态：`一致 / 不同 / 仅 A 有 / 仅 B 有`
- 口播："**'没表态'不算'一致'**——一致率只在两边都表过态的字段上算，
  否则'核得少'反而显得'一致率高'"

**用途建议**：
- `机器 vs 核对人` → 看机器错在哪，用来改提示词
- `张三 vs 李四` → 看两个人哪里理解不一致，用来统一口径

**必讲的三个坑**：

1. **`pnpm` 不在 PATH** → 一律 `corepack pnpm …`；`pnpm check` / `pnpm build`
   这种嵌套调用会失败，要拆开跑 `typecheck` / `test` / `-r build`。
2. **重建金标准必须两步**：`gold:rebuild` = `gold_normalize --apply-reconcile`
   + `gold_fix_units --apply`。少第一个 → 文章数静默变成 230；
   少第二个 → 冲掉带单位三列的修正。
3. **准确率数字经历过一次口径切换，新旧不能直接比**：

| | 严格 1:1（旧） | 覆盖率（现行） |
|---|---|---|
| Sheet1 | 63.6% | 63.6% |
| Sheet2 | 73.8% | 73.8% |
| Sheet3 | 35.9% | **45.9%** |
| 合计 | 49.2% | **58.1%** |

> 口播："差的 8.9 点**全部来自 Sheet3 口径变化**（分母 27498 → 12333），
> **不是抽取变好了**。旧口径下'漏抽'占总失分 41.2%，换口径后只剩 11.5%——
> 说明那一块大半是'结局行 1:1 配对'造成的假象。"

## 附录 D · 录制时可能卡住的 FAQ

| 现象 | 原因 / 处理 |
|---|---|
| 顶栏按钮点不动 | 有后台任务在跑（按钮 disabled）。等任务条结束，或「刷新字段」 |
| 提交时提示"未设置，暂不能提交" | 核对人没填。右上角输入框填名字后回车 |
| 点「抽取」很久没动静 | 单篇几分钟正常；点「展开日志」看进度 |
| 导回被拒绝 | 文件署名与当前核对人不一致。改成署名者，或勾「忽略署名异常」 |
| e2e 莫名其妙失败 | 多半是**端口被别的进程占了**（比如上次验收留下的打包应用）。检查 43130/43131 |
| 导出表里少了行 | 那几行的结局被「丢弃」了。看「核对汇总」页的裁定明细 |
