# 四步桌面工作流 0.2.5

可双击项目根目录的“启动四步提取客户端.bat”，自动绑定当前项目工作区。\n\n新版入口为 `build/desktop-workflow/ArticleAgent-Workflow-0.2.5-portable.exe`。双击后使用本项目目录作为工作区，保留现有 PDF、解析缓存与 API 设置。首次找不到目录时选择包含 Datas、build、runtime 的项目目录。

## 医生操作

1. 在顶部选择论文，填写核对人，在“基础字段”点击“提取基础字段”。可逐字段查看原文、修改和确认。
2. 在“结局候选”生成候选。系统同时读取正文、可用的解析表格和同编号附件，列出原文名称、量表、分域及来源。
3. 在“人工选择”只勾选需要汇总的结局名称，点击“保存选择”。不需要选择组别、时点或统计口径。可以搜索、修改候选名称和量表，或补加遗漏结局。
4. 在“选中结局汇总”点击“汇总所选结局／重试缺口”。结果按结局、组别、时间窗、绝对值或较基线变化等口径展开。每个数值可点击原文来源，修改后单独记录核对人。确认仅表示该条已由当前核对人检查。

选择改变后，上次结果会标记为过期，需再次汇总。再次汇总会清除旧结果的确认标记，保留并标注已有人工数值修改。请检查这些人工修改是否仍适用。

“已完成”表示阶段处理结束及本地证据规则通过，不代表已取得临床金标准正确率。待核对项包括缺少时点、引用无法定位、组别冲突、缺少附件、区间边界不能同源定位以及 API 失败。系统会保留这些缺口供人工检查。只在正文中提到但没有提供数值的结局可以没有数值行。

## 结果与缓存

正式状态存放于 `build/workflows/<年份>/<编号>/workflow.json`。选择版本、核对人、人工修改、运行记录、来源 PDF 身份都在这里保存。历史结果在同目录的 history、runs 中。每篇论文独立加锁，运行中不允许同时更改选择。

原文材料缓存在同目录的 materials 文件中，按 PDF 内容和解析块内容共同识别版本。补充或重新解析文件后重新生成候选。原始 API 响应在 `build/workflow-llm-cache`，成功结局检查点在论文目录 checkpoints 中。重试会复用已有成功响应，不需要重复解析全部文件。失败请求不会当作成功结果缓存。关闭客户端后重新打开可继续查看状态并重试。

附件约定为同目录的“论文编号-数字.pdf”，例如 2016-01-01.pdf。扫描附件没有原生文字时会提示需要解析，不能保证其候选已完整覆盖。

Excel 包含“基础字段”“结局选择”“结局全部时点”“缺口及待核对”四张表。CSV 导出结局长表。SD、SE、CI 两界、IQR 两界分别保存，未报告值留空。均值及其离散度、点估计及其区间需要相同来源。均值数据与组间差单独保存，不会合并成一行。正文和表格重复返回的同一组别时点会合并，数值冲突则保留各来源并提示核对。原生文字与解析值不同也会提示，可能来自负号编码或段落跨页。

API 使用工作区已有的 `runtime/llm.local.json`，也可在客户端“设置”里修改。密钥不打进便携程序。新流程的真实 API 调用仍会将论文材料发送至当前配置服务。

使用 Responses 协议时，可在「设置 → API 配置 → 各阶段的思考强度」分别设置基础信息、结局候选、常规结局汇总、疑难字段复核和最终复核的档位。项目默认依次为中、高、中、高、高。选择自动时由服务端决定该阶段的档位。

基础信息始终只使用自己的档位。有可定位证据且常规汇总仍有待核对数值或单位时，程序用疑难字段档位补提；经原文校验通过的值才补入结果。在汇总页点击「AI 最终复核」，用评审模型和最终复核档位检查当前结果，显示带原文出处的疑点。人工编辑后可以重新复核。独立的语义评审脚本也读取最终复核档位。

## 开发与验证

- `node tools/desktop_workflow_make.mjs` 编译五个内部包、检查前端类型、构建前端并打包 Windows 便携版。新输出目录与旧版本分开。
- `npm run workflow:test` 检查选择版本、同篇并发、证据和数值规则、去重、导出以及完整响应超时。
- `npm run workflow:ui-check` 使用真实页面与隔离数据验证人工操作，不调用付费 API。
- `npm run workflow:desktop-check` 启动已打包 Electron，验证本地服务、PDF 与随包 Node/PDF.js。
- `node tools/workflow_validate_26.mjs` 为26篇11月参考论文调用实际 API，选择和结果隔离在 `build/workflow-validation/2026-11-21`。基础字段复用已有抽取，候选和结局汇总使用新流程。参考表中的宽泛中文/英文结局与原文具体量表不一定一一对应，自动名称对齐率不能作为抽取准确率。
- “历史字段核对”保留原来的核对页面。新四步流程的状态独立保存，不会覆盖旧的抽取 JSON 或人工金标准。
